# ARTEX 데스크톱

기존 한국어 ARTEX를 Electron + Go + SQLite 로컬 앱으로 전환한 프로젝트입니다. Go가 업무 데이터·트래픽·증거를 저장하고 Electron이 창과 백엔드 수명 주기를 관리합니다. 원본 [Autumn-27/ARTEX](https://github.com/Autumn-27/ARTEX)의 기능과 한국어 화면을 재사용합니다.

UI는 [andongmin94/neobrutal-ui](https://github.com/andongmin94/neobrutal-ui)의 Mono 색상 테마·컨트롤 동작을 적용합니다. 웹 화면과 앱 시작·오류 화면, 코드·로그의 글꼴은 로컬 Pretendard Variable 하나로 통일하며 글꼴 선택 설정은 제공하지 않습니다. 글꼴 파일과 SIL Open Font License를 앱에 포함하고 실행 중 원격 글꼴을 요청하지 않습니다. 현재는 개발 검증 중이며 정식 릴리스가 아닙니다. 설치·서명·자동 업데이트와 도구 런타임 준비 상태는 [개발 계획](docs/development-plan.md)에 실제 검증 범위대로 기록합니다.

작업 생성 → 에이전트 탐색 → 취약점과 증거 검토 → 수정 → 재검증 흐름을 제공합니다. 화면을 한국어로 바꾸었으며 기본 에이전트 지침, 오류·상태 메시지, 알림, 보고서도 한국어로 제공합니다. API 필드, 도구 이름, 명령 옵션 및 상태 코드는 변경하지 않습니다.

> 원본의 저작권과 [AGPL-3.0 라이선스](LICENSE)는 유지합니다. 아래의 원본 사용 안내와 면책 조항을 확인하세요. 이 문서는 번역·운영 안내이며 추가적인 사용 허가를 부여하지 않습니다.

## 먼저 준비할 것

앱 실행에 별도 DB 서버가 필요하지 않습니다. 실제 에이전트 작업에는 LLM 설정과 해당 작업에 필요한 도구 준비가 필요합니다. 기본 테스트는 임시 SQLite와 로컬 HTTP/모델 fixture를 사용합니다.

**소스 검토와 작업 폴더 안의 로컬 실행부터 시작하세요.** Windows x64 앱은 고정 버전 PowerShell·Python·Node.js·Git을 포함하고, 검증된 도구를 작업 폴더 접근과 네트워크 차단을 적용한 환경에서 실행합니다. **시스템 → 시스템 설정 → 외부 실행 도구**에서 도구별 버전·사용 가능 여부·차단 이유를 확인하세요. 도구의 네트워크 요청과 브라우저 자동화가 모두 준비된 상태는 아닙니다. Go의 기존 HTTP 도구·대상 범위·승인 정책은 유지합니다.

파일 읽기는 모델이 실제 도구를 호출하고 기존 승인·차단 정책을 통과해야 수행됩니다. 기본 탐색·읽기는 `LS`·`Read`를 사용합니다. `Glob`·`Grep`는 주 에이전트·계획 에이전트에 제공되며 Worker에는 제공되지 않습니다. `Write`·`Edit`·`MultiEdit`도 외부 명령 차단 대상이 아니므로 「실행 환경 미준비」를 읽기 전용 모드로 해석하지 마세요. 검토용 복사본과 필요한 도구 제한을 사용하고 도구 실행 기록을 확인하세요.

외부 LLM을 연결하면 대상 응답, 명령 출력, 첨부 파일 및 증거 일부가 모델 제공자에게 전송될 수 있습니다. 승인된 모델을 사용하고 운영 자격증명과 실제 개인정보를 테스트 데이터에 넣지 마세요. 프록시와 관리자 콘솔은 외부에 공개하지 마세요.

### 화면만 확인하기 — 실제 테스트 없음

Node.js 22 이상을 설치한 환경에서 다음 명령을 실행하세요.

```bash
git clone https://github.com/andongmin94/ARTEX.git
cd ARTEX
cd web
npm ci
NEXT_PUBLIC_MOCK=1 npm run dev
```

터미널에 표시되는 주소를 여세요. 데모의 취약점·명령·재검증 기록은 가상 데이터이며 실제 대상에 요청을 보내지 않습니다.

Windows PowerShell에서는 마지막 명령 대신 다음을 사용합니다.

```powershell
$env:NEXT_PUBLIC_MOCK = "1"
npm run dev
```

### Electron 빌드와 실행

Node.js 22 이상과 `go.mod`에 명시된 Go 1.26.3이 필요합니다.

```powershell
cd web
npm ci
cd ../desktop
npm ci
npm run build
npm start
```

Go가 PATH에 없으면 빌드 전에 `ARTEX_GO`에 실제 Go 실행 파일의 절대 경로를 지정합니다.
Windows 실행 폴더는 `desktop`에서 `npm run package`로 생성합니다. 출력된 `dist/ARTEX-win32-x64/ARTEX.exe`를 실행합니다. `npm run package:installer`는 사용자별 설치·업그레이드·제거를 검증할 서명되지 않은 개발 설치 프로그램도 만듭니다. 기존 출력 폴더는 먼저 보존해야 합니다. 공식 도구 배포물의 첫 다운로드에는 인터넷이 필요하며 이후에는 SHA256을 대조한 로컬 캐시를 사용합니다. 현재 생성물은 정식 릴리스가 아닙니다. 자세한 도구·설치·서명 절차는 [데스크톱 개발 안내](desktop/README.md)를 확인하세요.

Electron 앱은 비밀번호 설정이나 로그인 없이 작업 화면으로 바로 열립니다. **시스템 → LLM**에서 모델을 설정하세요.
앱 세션을 확인한 뒤 Go가 실제 API 인증 토큰을 자동으로 발급합니다. 기존 데이터의 비밀번호는 변경하지 않으며, 일반 브라우저로 Go 서버를 단독 사용하는 경우에는 비밀번호 로그인을 유지합니다.
데이터는 Electron `userData` 아래의 `config.json`, `jwt.key`, `skills/`, `data/artex.sqlite` 및 기존 트래픽·증거·작업 폴더에 저장됩니다. `--artex-home=절대경로`는 명시적으로 다른 데이터 홈을 사용할 때 지정합니다.
기존 사용자 DB·설정·증거를 자동 삭제하거나 PG 데이터를 가져오지 않습니다.

## 기본 설정

### SQLite

Go만 로컬 DB 연결을 소유합니다. DB 선택 옵션이나 PG 병행 지원은 제공하지 않습니다.
배열은 검색 가능한 관계 테이블로 저장하고 IP/CIDR는 Go에서 정규화합니다. 작업 보관 패키지는 SQLite 형식4를 사용하며 이전 PG 형식 자동 변환은 제공하지 않습니다.

### LLM

**ChatGPT 구독으로 사용하기**

1. **시스템 → LLM → ChatGPT 구독 → Continue with ChatGPT**를 누릅니다.
2. 기본 브라우저에서 ChatGPT 계정으로 로그인하고 ARTEX의 구독 사용에 동의합니다. 현재 공식 공개 연결은 Plus·Pro 계정을 대상으로 하며 실제 계정에서 제공하는 모델을 사용합니다. 앱 비밀번호나 API 키를 입력하지 않습니다.
3. ARTEX로 돌아와 첫 연결 안내를 확인하고, **ChatGPT 구독 모델 → 선택 모델 활성화**를 누릅니다. 작업·대화·목표 분해는 이 활성 모델을 사용하며, 작업이나 에이전트에 별도 모델을 지정했다면 그 설정이 우선합니다.
4. 사용량은 구독 카드의 **사용량 관리**에서 확인합니다. ChatGPT 구독 한도는 다른 연결 앱과 공유합니다. 한도 소진 시 자동으로 유료 API 설정으로 전환하지 않습니다. 직접 지정한 작업의 모델 체인은 기존 전환 정책을 따릅니다.

브라우저 로그인은 5분 안에 완료해야 하며 **연결 취소**로 중단할 수 있습니다. Go 서버를 일반 브라우저에서 사용할 때는 카드에 나타나는 인증 링크를 직접 여세요. 해당 ARTEX 서버와 로그인 브라우저는 같은 PC에서 실행해야 loopback callback이 돌아옵니다.
**로그아웃**은 ARTEX의 구독 토큰을 지우며 앱의 작업·증거·로그인은 유지합니다. 원격 동의 해제가 확인되지 않으면 앱이 오류를 표시하므로 ChatGPT의 연결/사용량 설정에서도 확인하세요. 하나의 앱 데이터 홈에는 한 계정의 등록 정보를 유지합니다.

Go가 공식 OAuth·PKCE 로그인, ID 토큰 검증과 토큰 갱신을 담당합니다. 토큰은 앱 데이터 홈의 `chatgpt/credentials`에 저장하며 Windows에서는 현재 사용자 DPAPI와 전용 파일 권한으로 보호합니다. Linux/macOS 코드는 전용 디렉터리/파일 권한을 적용하지만 해당 OS의 실제 실행은 미검증입니다. 토큰을 SQLite 프로필·화면 저장소·API Key 입력란에 넣거나 다른 앱의 로그인 파일을 가져오지 않습니다.
구독 연결은 공식 공개 Responses 엔드포인트의 스트리밍·`store:false` 계약을 사용합니다. 모델에 보낸 검토 소스는 외부 모델 입력이므로 실제 비밀번호·개인정보가 없는 복사본을 사용하세요.
공식 연결 조건과 한도는 [Sign in with ChatGPT 안내](https://developers.openai.com/siwc/quickstart)와 [구독 세션·사용량](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)을 확인하세요.

2026-10-07 Windows 실제 계정 검증에서 로그인·구독 동의, 모델 목록 조회·활성화, 같은 데이터 홈 재시작 후 연결 유지와 GPT-6-Astra의 `OK` 응답을 확인했습니다. 서버가 `Content-Type`을 생략한 응답도 SSE 본문과 `response.completed`를 검증합니다. JSON·HTML·완료되지 않은 스트림을 성공으로 처리하지 않습니다.

**API 키로 사용하기**

웹 화면의 API 설정을 사용하거나 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`를 지정할 수 있습니다. 선택 환경 변수는 `ARTEX_LLM_PROVIDER`, `ARTEX_LLM_MODEL`, `ARTEX_LLM_BASE_URL`, `ARTEX_LLM_PROXY`입니다.

**시스템 → LLM → 생성**에서 이름, 형식, 모델, API Key를 입력합니다. 형식은 사용하는 API에 맞춰 Anthropic, OpenAI (Chat Completions), OpenAI (Responses API) 중 선택하고, 별도 게이트웨이나 로컬 모델 서버를 사용하면 실제 Base URL도 입력하세요.
**연결 테스트 → 생성 → 카드의 활성으로 설정** 순서로 진행합니다. 새 API 프로필은 생성만으로 활성화되지 않습니다. API 키 방식의 프로필은 키가 비어 있으면 사용할 수 없으므로, 키가 필요 없는 로컬 서버도 이 입력 조건을 확인하세요.
여기서 API Key는 모델 호출용 키이며 앱 로그인 비밀번호가 아닙니다.
입력·출력 상한, 컨텍스트 윈도우, 재시도, 장애 조치는 서로 다른 설정입니다. 화면의 한국어 도움말을 확인하세요.

### 실행 주소와 종료

Electron은 Go를 loopback 동적 포트에서 시작하고 실제 ready의 PID·주소를 확인합니다. 매 실행마다 생성한 앱 세션 키를 검증해 JWT를 자동 발급하며, API는 JWT와 앱 세션을 함께 확인합니다.
렌더러의 Node 접근을 끄고 context isolation·sandbox·CSP·제한된 IPC와 탐색 정책을 적용합니다. 앱 종료나 부모 stdin EOF는 Go의 정상 종료를 요청합니다.
렌더러 격리가 외부 명령의 OS·네트워크 격리를 보장하지는 않습니다. 준비되지 않은 외부 도구 상태는 별도 표시하고 실행을 차단합니다.

## 첫 작업: 로컬 프로젝트 소스 검토

1. **검토할 복사본을 준비합니다.** 원본 프로젝트와 분리한 폴더를 만들고 실제 비밀번호·API 키·개인정보가 없는 소스와 설정 예제를 사용합니다. 외부 LLM을 쓸 때는 이 코드의 모델 전송도 확인하세요.
2. **기능 → 작업 → 새 작업**을 엽니다. 이름은 선택 사항이고 **설명**, **목표**는 필수입니다. 「LLM 설정 체인」을 지정하지 않으면 에이전트에 지정된 모델 또는 전역 활성 설정을 따릅니다.
3. **설명에 소스를 전달합니다.** 아래 예시의 절대 경로를 검토용 복사본 경로로 바꾸거나 「파일 업로드」로 필요한 소스를 선택합니다. 업로드는 선택한 파일을 앱 데이터 홈에 복사하고 그 절대 경로를 설명 끝에 추가합니다. 폴더 경로를 적는 것만으로 프로젝트를 가져오거나 색인하지는 않습니다. 모델이 실제 `LS`·`Glob`·`Grep`·`Read`를 호출했는지 확인해야 합니다. 「작업 공간」은 앱 데이터 폴더의 파일 관리 화면이며 PC의 임의 프로젝트 폴더를 여는 탐색기가 아닙니다.
4. **생성 후 실행 기록을 확인합니다.** 「생성」을 누르면 실행 가능한 모델 설정에 따라 목표 분해와 실행을 자동 시작합니다. 모델이 없으면 대기하며, 동시 실행 제한이 켜져 있으면 빈 슬롯이 생길 때 시작합니다. 작업 상세의 「세션」과 「도구 실행」에서 실제 읽은 파일, 도구 결과, 실패 이유를 봅니다. 상세의 「차단 승인」 또는 **시스템 → 승인 기록**에서 호출을 검토해 「허용」/「거부」를 선택합니다. 범위를 벗어나면 상세 상단의 「일시 중지」를 사용하고 준비 후 「재개」합니다. 작업 상태가 완료여도 요청한 파일을 읽지 못했다면 소스 검토 완료로 판단하지 마세요.
5. **발견 사항을 검토합니다.** 「취약점 발견」에서 파일·줄·호출 경로와 판단 근거를 확인합니다. 소스에서 의심되는 문제와 실제 실행 환경에서 재현한 문제를 구분하고, 수정본의 같은 경로를 다시 확인합니다. 재검증에 필요한 도구의 사용 가능 상태와 작업 폴더·네트워크 제한을 확인하세요. 브라우저와 외부 네트워크 연결이 필요한 도구는 아직 차단 상태입니다.

처음에는 전체 프로젝트보다 로그인·권한·파일 업로드 등 한 기능의 컨트롤러, 서비스, SQL 매퍼, 관련 설정부터 검토하는 편이 결과를 확인하기 쉽습니다.

**이름 예시**

```text
demo-app 로그인·권한 소스 검토
```

**설명 예시 — 경로는 실제 검토용 복사본으로 변경**

```text
소스 폴더: C:\security-lab\app-copy
이번 작업은 로컬 소스 검토만 수행한다.
먼저 LS로 관련 파일을 찾고 Read로 실제 내용을 확인한다.
사용 가능한 경우 Glob/Grep을 보조로 사용한다.
로그인, 세션, 서버 측 권한 검사, SQL 매퍼, 파일 업로드 흐름을 검토한다.
파일 변경, 명령 실행, HTTP 요청, DB 접속, 외부 MCP 호출은 하지 않는다.
검토한 파일과 읽지 못한 파일을 구분하고, 비밀값은 결과에 출력하지 않는다.
```

**목표 예시**

```text
보안상 의심되는 경로를 파일·줄·호출 흐름과 함께 정리한다.
예상 영향, 수정 방향, 격리된 실행 환경에서 추가 확인할 조건을 제시한다.
소스만으로 확정할 수 없는 문제를 실제 재현한 취약점으로 보고하지 않는다.
```

설명의 제한은 모델 지시입니다. 파일 접근 권한이나 네트워크 격리를 강제하지 않으므로 기존 승인·차단 규칙, OS 권한, 별도 검토 환경을 함께 사용해야 합니다. **시스템 → 명령 차단**의 「차단 범위」에 활성화한 도구에만 규칙 검사가 적용됩니다. 소스 검토 전에 파일 수정·외부 요청 도구의 범위와 규칙을 확인하세요.

## 검사 대상은 로컬인가, 개발 서버인가?

**첫 단계는 소스 검토와 격리한 로컬 복제본입니다.** 코드만 검토할 때는 대상 서버를 실행할 필요가 없습니다. 실제 로그인·권한·세션·업로드의 요청과 응답을 확인하려면 대상 앱을 실행해야 합니다. 로컬 검증 후에는 운영과 같은 인증·배포 설정을 갖춘 별도 검증 환경에서 차이를 확인합니다. 이는 코드 검토와 배포 후 구성 검사를 함께 다루는 [OWASP WSTG의 검사 흐름](https://wstg.owasp.org/v4.2/3-The_OWASP_Testing_Framework/0-The_Web_Security_Testing_Framework/)을 이 프로젝트에 적용한 권장 순서입니다.

| 대상 | 확인할 수 있는 것 | 사용 순서 |
| --- | --- | --- |
| 로컬 소스 복사본 | 권한 검사 누락, 위험한 SQL/파일 처리, 설정과 호출 흐름 | 현재 ARTEX에서 먼저 시작할 범위. 실행 재현은 별도 확인 |
| DB·외부 연동까지 분리한 로컬 실행본 | 테스트 계정의 인증·권한, 세션, 입력·업로드의 실제 동작 | 앱 전용 실행 도구가 준비된 뒤 로컬 기술 검증 |
| 운영 설정을 재현한 별도 검증 서버 | HTTPS·프록시·SSO·배포 권한·쿠키 등 로컬과 다른 설정 | 일반적인 후속 보안 검증 단계. 아래 원본 사용 안내에 따라 현재 ARTEX의 온라인 서버 스캔 대상으로 안내하지 않음 |
| 공동 개발 서버 / 운영 서버 | 실제 사용자·공유 DB·외부 시스템에 영향을 줄 수 있음 | 이 README의 ARTEX 실행 대상 범위에 포함하지 않음 |

ARTEX가 로컬에서 실행되는 것과 검사 대상이 로컬인 것은 별개입니다. Electron이 표시하는 Go의 동적 loopback 주소는 ARTEX 관리 API입니다. 대상 URL에는 검사할 앱의 주소를 적어야 합니다. 예를 들어 검토용 앱을 로컬 8080에서 실행했다면 대상은 `http://localhost:8080/`입니다. 이 주소는 예시이며 대상 앱의 실제 포트와 경로를 확인한 뒤 사용하세요.

### 로컬 검사 대상 준비

- 앱 주소가 localhost여도 DB·SSO·메일 등은 각 설정의 목적지에 연결됩니다. 공유 개발·운영 시스템에 연결되지 않는지 확인하세요.
- 소스 검토에는 비밀번호·토큰·개인정보를 제거한 복사본을 사용하세요. 실행 검증에는 별도 검증 DB, 가상 데이터와 테스트 계정을 준비하세요.
- 대상·계정·요청 종류의 승인 범위를 확인하고, ARTEX의 승인·차단 규칙과 별도 실행 환경에 같은 제한을 적용하세요. 앱 전용 실행 도구의 준비 상태는 [개발 계획의 M4](docs/development-plan.md)를 확인하세요.

## 재검증과 증거

재검증은 원래 전체 작업을 다시 시작하지 않고 독립 에이전트 세션으로 수행합니다. 결론은 **재현 가능**, **수정됨**, **확인 불가**로 구분합니다. 성공적으로 완료되고 수정 효과가 확인된 경우에만 취약점 처리 상태를 자동으로 수정됨으로 변경합니다. 실패·중지·확인 불가에서는 기존 상태를 유지합니다.

HTTP 증거는 정상 대조군, 취약점 입증, 추가 검증, 보조 증거로 구분하여 재현 순서대로 연결합니다. 연결된 증거 스냅샷은 원본 트래픽 목록과 별도로 유지됩니다. TCP 등 HTTP가 아닌 취약점은 명령 출력·로그 등 다른 검증 가능한 증거를 사용합니다. 도메인과 시각이 같다는 이유만으로 관련 트래픽이라고 단정하지 마세요.

재검증 기록은 취약점 상세와 세션에서 확인합니다. 원본에서 제공하지 않는 재검증 내역의 보고서·보관 패키지 포함이나 자동 패킷 연결 기능을 이 번역이 추가하지는 않습니다.


상세 사용법: [다중 트래픽 증거](docs/finding-traffic-evidence.md), [API 조사 참조 설명서](skills/api-recon/reference.md), [별도 질문 /btw](sidequestion/README.md).

## 에이전트, MCP, 스킬

**목표 분해 에이전트**가 최종 목표와 실행 제약을 등록합니다. **계획 에이전트**가 상황을 읽고 의도를 배정하며, **실행 에이전트**는 배정된 의도 하나를 수행하여 사실·자산·취약점을 저장합니다. **주 에이전트**는 사용자의 지시와 질문을 연결합니다. 보고서·재검증 에이전트는 각각 보고서 작성과 수정 확인을 담당합니다.

원격 MCP는 Streamable HTTP와 기존 SSE 전송을 사용합니다. 서버를 등록한 뒤 에이전트별 접근 권한을 지정하세요. SSE 서버는 일반적으로 `/sse` 주소를 사용하며 인증 헤더는 서버 요구 사항에 맞춥니다. Electron의 로컬 `stdio` MCP는 앱 매니페스트의 도구 key 또는 검증된 실행 파일 절대 경로로 실행합니다. 호스트 PATH에서 `npx` 등을 찾거나 실행 중 패키지를 자동 설치하지 않습니다. MCP에도 작업 폴더·네트워크·환경변수 격리를 적용하며 기존 에이전트별 접근 권한과 도구 호출 승인을 유지합니다.

스킬은 `SKILL.md`와 관련 스크립트·참조 파일로 구성합니다. 스킬을 불러올 때 연결된 MCP 도구를 공개할 수 있습니다. 가져오는 외부 스킬의 설명·본문과 외부 MCP의 도구 설명은 해당 공급자가 작성한 언어로 표시될 수 있습니다.

ScopeSentry는 「자산 동기화」에서 MCP 주소와 API Key를 등록한 뒤 프로젝트 또는 작업별로 선택한 자산 유형을 가져옵니다. 기업 키워드는 범위 참고 정보이며 자동 자산 소속 판정과 다릅니다.

## 저장 구조

전역 **자산 그래프**는 도메인, IP, 서비스, 애플리케이션, 엔드포인트를 관리합니다. 작업별 **탐색 그래프**는 목표, 의도, 사실, 취약점, 힌트와 압축 요약을 저장합니다. 두 그래프는 자산 앵커로 연결됩니다.

Worker의 완료, 취약점 발견, 사용자 목표·힌트 변경 등이 계획 라운드를 깨웁니다. 실행 과정 검색을 통해 다른 Worker의 관찰을 재사용할 수 있습니다. 계획 할 일 목록은 같은 실행 프로세스에서 계획 라운드 사이에 유지됩니다. 서버 재시작을 넘어 모든 메모리 상태가 자동 보존된다고 가정하지 마세요.

기존 DB에 저장한 사용자 프롬프트, 이름, 과거 결과는 번역을 위해 일괄 덮어쓰지 않습니다. 기본 프롬프트를 한국어로 사용하려면 에이전트 편집 화면에서 기본값을 확인하거나 복원하세요. 사용자 정의 프롬프트는 필요한 부분을 직접 수정해야 합니다.

## 업데이트와 백업

개발 실행은 이 포크의 소스에서 UI·Go·고정 도구를 함께 다시 빌드하세요. Go 자체 업데이트와 Docker/PG 시작 경로는 제거했습니다. 서명된 설치 버전의 Electron 업데이트는 배포 정보의 고정 RSA 키, 다운로드 SHA256, 파일 목록과 Windows 코드 서명을 검증한 뒤 앱 전체에 적용합니다. 설치 준비 응답과 현재 데이터 백업이 성공한 뒤 앱을 종료합니다. 새 앱의 실제 준비 확인에 실패하면 실행 버전 포인터를 이전 버전으로 되돌립니다. 사용자 DB를 자동으로 이전 상태로 덮어쓰지 않습니다. 현재 개발 설치물은 자동 업데이트를 구성하지 않으며 공인 서명·배포 서버는 별도 준비가 필요합니다.

**시스템 → 시스템 설정 → 백업과 복원**에서 백업을 만들거나 검증한 백업을 새 폴더로 복원할 수 있습니다. 백업 전에 Go를 정상 종료하고 SQLite의 백업 기능으로 업무·트래픽 DB를 저장하며 설정·JWT 키·스킬·증거를 함께 검증합니다. 복원은 기존 데이터 폴더를 덮어쓰지 않으며 새 폴더로 재시작할 수 있습니다. 기본 자동 백업은 하루 첫 정상 종료에 데이터 홈 밖의 `ARTEX-backups`에 새 스냅샷을 저장합니다. 이전 백업은 삭제하지 않습니다. 백업에는 인증 정보가 포함되므로 사용자가 지정한 보호된 로컬 위치에 보관하세요. Windows DPAPI로 보호한 구독 인증은 같은 Windows 사용자 환경에서 사용합니다.

## 개발 및 검증

```bash
# 프런트엔드
cd web
npm ci
npm run check:korean
npm run test:input
npx tsc --noEmit
npm run build:static
cd ..

# 실제 modernc와 독립된 SQLite 임시 파일로 실행
go test -count=1 -timeout 180s ./...
go build ./cmd/artex

# 실제 Electron + Go 검사
cd desktop
npm run build
npm run test:electron
```

프런트엔드만 개발할 때는 `cd web && npm run dev`를 사용합니다. 실제 대상 테스트나 외부 LLM 호출은 기본 검사에 포함하지 않습니다.
Playwright의 Electron 지원은 experimental API입니다. 설치·서명·OS 네이티브 IME·Windows 디스플레이 배율은 DOM/Electron 자동화와 구분합니다.
